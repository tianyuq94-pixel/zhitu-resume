# 三入口工作室与公开 AI 分身

## 入口

- `/`：三张入口卡片（AI 分身、求职 Agent、原版求职网站）。
- `/me`：聊天式公开分身。访客无需手动注册。
- `/agent`：既有求职 Agent，招聘链接读取已移除。
- `/app`：原版工作台，不再跳转 Agent；保留原登录注册页面及资料完善流程。有访客会话时可继续使用原版工具。

## 资料与说话风格

唯一公开资料源为 `backend/app/persona_public.json`。姓名、教育、项目和实习依据本人已确认简历和项目资料；电话与邮箱已获本人授权在被问及时回答。联系方式不随公开名片接口返回。

修改 facts 可补充公开经历；修改 style、welcome、unknown 与每条事实的 text 可调整口吻。不应把用户上传文件、访客私有资料库、数据库密钥或私人聊天记录接到该文件。未来增加管理页面时必须先有管理员身份校验，不能向访客开放资料修改接口。

当前版本每轮调用 DeepSeek，根据公开资料和最近的聊天上下文自然生成 answer，而非选择固定段落。fact_ids 仅用于标注使用的资料；普通闲聊可以没有 ID。无效结构或未知 ID 会兜底。提示词约束本人事实、隐私和承诺边界，但 ID 校验不等于逐句事实证明，生成式回答仍可能出错，需要持续测试与校正。当前资料量小，直接提供精选公开资料，不是向量检索，也未做模型微调。

薪资、到岗、未公开私人信息与承诺类问题交由本人确认。界面始终标注 AI 分身，输入动画不代表本人在线。聊天仅保留在当前页面内存，刷新后清空；生成时最近 12 条消息会发送至模型服务，不应输入敏感信息。

## 验证与部署

执行后端 pytest 和前端 build。真人资料不用于创建测试用户；测试中校验公开名片不含联系方式、私有资料不进入提示、未知事实兜底、CSRF 与输入约束。

本地整合未自动发布。上线需包含 persona_public.json 服务端文件，确认现有数据库已迁移至 0011_extra_facts，检查首页、聊天、登录、Agent 和原版功能均能直接访问。
