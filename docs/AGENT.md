# 求职 Agent V1

## 已实现

- 默认入口 `/agent`，网站首页、登录与注册入口跳转工作台。
- `POST /api/v1/auth/guest` 建立或续期签名访客 Cookie；简历、成果和任务仍按用户 ID 隔离。访客 Cookie 失效后不能跨设备找回。
- 真实主简历上传、解析、原文件预览、文字确认与私有保存。
- 公司可选、岗位必填；任务名为 `公司 · 岗位`，未填公司时只显示岗位。
- 工具调用选择器根据简历、岗位、已有匹配结果、工具执行摘要和用户补充决定下一步。工具白名单为岗位分析、定制简历、面试准备、询问用户、完成任务。服务端校验前置依赖与工具名。
- 未提供完整 JD 时生成明确标注的通用能力清单，不将推测说成公司实际要求，不展示该模式的匹配数字。
- 面试准备只生成方案；用户点击后进入独立模拟面试准备页，再自行开始。
- 定制建议逐条采纳、保留原文或自定义；姓名及全部条目确认并保存后才能导出 PDF/Word。
- 数据库保存任务步骤、消息、分析与准备方案，定制简历通过 ID 关联；页面刷新后手动继续。页面关闭后不会启动后续步骤。
- revision 原子锁阻止双标签页重复执行同一版本；执行中断的锁十分钟后允许恢复。极端的进程退出发生在工具落库与任务关联之间时，恢复可能重复生成一个成果版本，暂不承诺跨工具的 exactly-once。
- 数据库固定窗口计数：每 IP 每小时 10 个新访客、每访客每小时 8 个任务、40 次步骤请求。旧版功能另有原有的接口频率限制。代理部署需验证客户端 IP 的可信获取，避免共享代理地址造成误限。

## 本地运行

在 backend 目录使用既有虚拟环境执行 `python -m alembic upgrade head`，然后运行 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`。frontend 目录运行 `pnpm dev`。

服务端密钥为 `AI_CAREER_DEEPSEEK_API_KEY`。操作系统/进程环境变量优先于 `.env`，更换后必须重启后端；不要把密钥发到聊天或提交 Git。

## 验证

`python -m pytest -q` 包含访客隔离、Cookie 身份复用、CSRF、任务命名、跳过与非法工具拦截、失败恢复、版本冲突、可选 JD、数据库限流、真实导出接口的集成测试。AI 返回由测试替身提供，数据库使用独立内存库。

`python tests/live_agent_smoke.py` 为显式运行的真实 AI 冒烟测试，仅提交脚本内人工构造的测试简历。会创建本地测试访客和任务并消耗 API 用量，不用于默认测试。

2026-09-11：用户更新本地密钥后，带完整 JD 和不填 JD 两种真实模型端到端测试均通过：岗位分析、定制简历、准备方案、PDF 与 Word 导出均成功，未创建模拟面试。模型一次提出多个工具时，只执行第一个获准工具，下一步重新根据持久化结果规划；有对应回归测试。自动化测试共 51 项通过。

## 成果优先的交互与建议过滤

- 活跃任务使用全宽成果工作区；不渲染工具步骤、执行摘要或过程消息。仅在需要用户补充时显示提问。
- 提交和分析期间提供等待动画，未完成的成果提供骨架占位；不模拟完成百分比。保留暂停、失败重试和断点恢复。系统减少动画设置下禁用动画。
- 完整简历与修改建议分开。服务端通过 Unicode 归一化、忽略标点空白、连接词与字符重叠度、序列相似度保守过滤无实质变化；宁可漏掉轻微改善，也不把换标点当成建议。此规则是文本差异门槛，不是对语义质量的绝对保证。
- 旧记录读取时同样分类，未修改条目保留原文并免确认；保存时再次执行规则，用户明确手动编辑的内容不覆盖。完整正文仍可编辑和导出。
- 2026-09-11 本轮前端构建通过，63 项后端测试通过，含旧记录、无建议保存、PDF/Word 导出、Word 原文保留和手动修改保护。浏览器检查了现有任务全宽成果、零有效建议空态及完整简历编辑入口。本轮未额外调用真实模型，未发布。
